## 骨架（Bug 型）

### 1. 现象

真实报错原文 / 真实行为，加最小复现命令。

### 2. 第一直觉与它的偏差（**必填**，ADR 没有、最容易丢的信息）

先记「我当时以为是什么」，再写实际是什么。

### 3. 排查路径

每条：假设 → 怎么验证 → 结论。**死胡同也要写，并说明为何此路不通。**
关键判断标注时效：`（记于修复后 X 分钟）` / `（回忆，可能失真）`。

### 4. 本质陈述卡

- **一句话**：
- **因果链**：因为 `<条件>` → 导致 `<机制>` → 产生 `<现象>`
- **边界**：必然发生 …… / 不会发生 ……
- **层级**：① 触发条件 / ② 机制 / ③ 根因 / ④ 系统性原因（本质只写 ③）
- **代码定位**：`文件:行号`（说不出行号，通常还没到本质）
- **解释力自查**：能解释 …… / **解释不了** ……
- **可切换性验证**：移除 → 消失（已验/未验）；加回 → 复现（已验/未验）
- **反例**：什么情况下同样的表象但不是这个原因
- **复核提示**：什么条件下本节失效
- **置信度**：高 / 中 / 低 ｜ **如果我错了，会怎么发现**：<可观测信号>

### 5. 修复方案与取舍

文件级改动表（文件｜改了什么｜为什么）＋ 影响面 ＋ 回退方式。

### 6. 验证

必写：**怎么确认是真好了，而不是没触发**。
环境跑不了的部分单列「未验证」，写明交给谁、在哪跑。
（只有「能编译」这条证据时，置信度上限是「中」。）

### 7. 沉淀

可迁移教训 ＋ 防复发措施（测试/断言/类型/校验/监控）；登记进 devnotes README 规则表。
