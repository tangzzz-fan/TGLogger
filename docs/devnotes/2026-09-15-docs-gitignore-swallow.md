# 裸 `docs/` 规则吞掉 `Docs/`：文档写好了，git 永远不收

`标签: bug 修复` | `模块: 仓库根 .gitignore / docs/` | `深度: BRIEF（本质陈述卡按 FULL 标准填）` | `状态: 已解决`

## 3 行速览

- **结论**：`.gitignore` 里裸写 `docs/`，在 macOS 大小写不敏感文件系统上会**连 `Docs/` 一起忽略**，于是 `docs/SWIFTUI_CONSOLE.md` 本地存在、README 也链了它，但 `git add` 静默不收 → 推到 GitHub 就是 404。
- **影响**：所有「先写文档、后入库」的流程都会踩；`TGFeatureFlag` 用的是同一份 `.gitignore` 模板，同样埋着这颗雷。已修（目录改小写 `docs/` + 删规则 + 留反例注释）。
- **细读建议**：只要知道「别写裸 `docs/`」就够了；想知道为什么大小写不敏感会放大成「静默丢失」，看 §4。

---

## 1. 现象

本轮要做的是「把 SwiftUI 控制台的口径讨论收成一篇文档」，写到 `Docs/SWIFTUI_CONSOLE.md`，并在 `README.md` / `DesignInfo.md` 里加了链接。文件在 Finder 和编辑器里都正常，`git status` 却**只显示那两个被改的 .md**：

```text
 M DesignInfo.md
 M README.md
```

新建的 `Docs/` 目录完全不出现 —— 不是「已修改」，不是「未跟踪」，是彻底不存在。

最小复现：

```bash
git check-ignore -v docs/SWIFTUI_CONSOLE.md
# .gitignore:9:docs/	Docs/SWIFTUI_CONSOLE.md
```

## 2. 第一直觉与它的偏差（必填）

**直觉**：`Docs/` 从来没被提交过，所以应该是「未跟踪」，`git status` 里会出现 `?? Docs/`。看不到就说明我写错路径了。

**实际**：路径没错，是被**忽略**了。而且忽略它的规则不是我以为的 `Docs/`，而是第 9 行小写的 `docs/` —— 我第一眼扫 `.gitignore` 时甚至没把这条规则和 `Docs/` 目录联系起来，因为「大小写不一样」。

偏差的代价：如果不查 `git check-ignore`，下一步动作会是「再确认一遍路径」「重启编辑器」，方向完全错。

## 3. 排查路径

1. **假设：路径写错了。** → `ls Docs/` 文件确实在。✗
2. **假设：`.gitignore` 里有 `Docs/`。** → 通读 `.gitignore`，没有 `Docs/`，只有 `docs/`。此时本该起疑，但我先跳到了下一条。✗（走了个弯）
3. **假设：有 `.git/info/exclude` 或全局 ignore。** → `git check-ignore -v` 直接指出是 `.gitignore:9` 的 `docs/`。✓（这一步一步到位）
4. **确认机制**：`git check-ignore` 明确报了「`docs/` 命中了 `Docs/...`」，说明匹配是大小写不敏感的。再验一次双向：删掉该行 → `git status` 立刻出现 `?? docs/`；加回 → 再次消失。

**死胡同**：第 2 步通读 `.gitignore` 时我按「字面相等」在找，而不是按「git 的匹配语义」在找，所以读完了还是没找到。教训是排查 ignore 不要人肉比对，直接上 `git check-ignore -v <path>`。

## 4. 本质陈述卡

- **一句话**：忽略规则用了「目录级 + 大小写不敏感匹配」的写法，把作者以为无关的另一个目录一起排除了。
- **因果链**：因为 `.gitignore` 写了裸 `docs/`（无前导斜杠、无目录锚定）→ 且 macOS 默认 APFS 大小写不敏感、git 的 `core.ignorecase=true` 让 ignore 匹配跟随这一设定 → 该规则同时命中 `Docs/`，整个目录被排除 → 产生「文件在磁盘上、被 README 链接，但 `git status` 静默不收、GitHub 上 404」的现象。
- **边界**：
  - 必然发生：在大小写不敏感的卷上，任何 `Docs/` `DOCS/` `docs/` 都命中这条规则。
  - 不会发生：仓库副本落在大小写敏感的卷上（如 Linux、Case-sensitive APFS）时，`Docs/` 不被 `docs/` 匹配 —— 但那种环境下文件本来就更容易被正常提交，所以现象只在**首次入库前**出现，一旦绕过就再也不会暴露。
- **层级**：① 触发条件 = 写了一条过宽的 ignore 规则；② 机制 = 大小写不敏感的路径匹配；③ **根因** = 忽略规则用「裸目录名」表达，而它的实际匹配语义（深度不限 + 大小写随文件系统）比作者意图宽；④ 系统性原因 = 模板 `.gitignore` 在多个仓库间复制，没人会去逐个验证每条规则的真实匹配范围。
- **代码定位**：`.gitignore:9`（修复前）。
- **解释力自查**：
  - 能解释：为什么文件在、`git status` 不显示；为什么 `git check-ignore` 有输出而作者「没写过这条」；为什么 README 链接会 404。
  - **解释不了**：为什么当初会写下 `docs/`。合理猜测是那条规则原本用于忽略文档生成物（jazzy/DocC 输出），从别处模板抄来 —— **（猜测，未验证）**。
- **可切换性验证**：**双向已验证**。移除规则 → `git check-ignore` 退出码 1、`git status` 出现 `?? docs/`；加回 → 再次命中。（记于修复后 2 分钟）
- **反例**：如果仓库里的 `docs/` 确实只放生成物（不手写、不需要入库），这条规则就是对的，不是 bug。`swift-protobuf` 的 `.gitignore` 里就是根锚定的 `/docs`，语义更窄，属于「写对了」的对照组。
- **复核提示**：当 `.gitignore` 改写、或仓库迁到大小写敏感卷后，本节机制不再适用，应重新评估。
- **置信度**：**高** ｜ **如果我错了，会怎么发现**：在大小写敏感的 APFS 卷上 clone 本仓库，若 `git check-ignore Docs/SWIFTUI_CONSOLE.md` 仍命中 `docs/`，则「大小写不敏感」这个解释不成立。

## 5. 修复方案与取舍

| 文件 | 改了什么 | 为什么 |
|------|----------|--------|
| `Docs/` → `docs/` | 目录名改小写 | 与 devnotes/specs 的约定目录一致；也避免以后有人再写 `docs` 规则时重新踩雷 |
| `.gitignore` | 删掉裸 `docs/`，留 3 行反例注释（含指向本手记的路径） | 注释是本仓库唯一能拦住下一个人的东西；规则本身无实际用途（doc 生成物不落 `docs/`） |
| `README.md:90` / `DesignInfo.md:64,78` | 链接 `Docs/…` → `docs/…` | 目录改名后的引用同步 |

**取舍**：没有用 `docs/` + `!Docs/` 的「负向再包含」写法。git 的规则是「父目录被排除时无法再包含其下的文件」，这种写法要靠先后顺序生效，读者几乎必然看不懂 —— 直接删规则更简单，也不会有人猜错。
**回退方式**：`git checkout .gitignore`，目录名 `mv docs Docs`，链接改回大写。

## 6. 验证

- **行为层面（已验证）**：修前 `git check-ignore -v docs/SWIFTUI_CONSOLE.md` 命中 `.gitignore:9`；修后退出码 1，且 `git status --short` 出现 `?? docs/`。双向都跑过，不是「删了以后没再出现」这种单向证据。
- **没被破坏的东西（已验证）**：`swift test` 19 个用例 / 6 个 suite 全绿（记录了修前基线，改动只碰 `.gitignore` 与 `.md`，未触及 Swift 代码）。
- **未验证**：GitHub 上「点开 README 链接能打开」要等提交推送后才成立 —— 本手记写完后文件仍处于未提交状态，「已修复」目前只覆盖到「git 会收它」这一层。

## 7. 沉淀

**可迁移教训**：判断「文件为什么没进 git」时，永远不要人肉比对 `.gitignore` 的字面；一条命令定案：

```bash
git check-ignore -v <path>   # 有输出 = 被忽略，并直接告出是哪个文件的哪一行
```

**防复发措施（已落地为机器守卫）**：`ci.yml` 在 checkout 之后、构建之前加了一步，比较「磁盘上 `docs/` 下有哪些文件」与「git 索引里跟踪了哪些」，多出来的直接报错并点名文件。选「逐文件比对」而不是「`git ls-files docs` 非空」，是因为前者能抓住增量漏网（比如以后又新写一篇文档、又被某条新规则吞掉），后者在 docs 目录已有入库文件时会静默放行。本地已做双向验证：对当前未入库的 4 个文件守卫正确报警（记于修复后 10 分钟）。CI 上的首跑是正式确认，见修订记录。
